**アイテムの追加・整理で壊れるので、カタログが落ち着くまで触らない。**

  7 層は層効果が未登録）。意図か抜けかは未確認
- 一律の値上げ (+2G) は −6.38pt・残金ほぼ不変（2026-09-17）── 金欠の負けランにだけ効く

再開するときの順番:

関連: リロールは BOT 方策で店 2 回まで（`AutoRunner.BotRerollCapPerShop`）。価格曲線 5,10,20… は

## 9. 測定の作法（2026-09-16 に 4 回踏んだ）

**値を振る前に、その値が結果に届く範囲にあるかを計装で確かめる。**

飽和を 4 回踏んだ: `dangerTarget` 天井 0.95 → `hpLowThreshold` 床 0.55 → `GoldComfort`（誤診）
→ `DangerFloor` 床 0.25。最初の 1 回で **70,000 ラン を無駄にした**（safetyHits スイープが単調に
なったのは見積り式のバグで、掃いていたのは「過大な見積りを何倍するか」という軸だった）。

サマリーに 2 行の計装を常設した。**スイープ前にまずこれを読む。**

```
危険度の内訳  : budget 平均 X / tail 平均 Y / budget が勝つ Z% / 出力 W (下限張付 a% 上限張付 b%)
金逼迫度 gp の分布: 平均 X / gp=0 (所持60G以上) Y% / gp=1 (無一文) Z%
```

**ただし「飽和している」は欠陥の証拠ではない。** `GoldComfort` は 36.8% が gp=0 に飽和していたが
それが正しい判断（もう十分持っているから店へ行け）で、解くと逆に悪化した（−4.5 〜 −12.3 z）。
`DangerFloor` も 46.9% 張り付いていたが解いても結果は動かなかった。
区別するには **その値が最終的な選択を何回変えているか**（McNemar の改善/悪化の件数）を見る。
