# 依頼: 大ダウンの取り逃しの診断（2026-11-26）

`docs/portfolio_metrics_20261126.md` の続きです。結果は同じファイルに **「⑭」** として追記してください（①〜⑬ は書き換えない）。
**この依頼は測定だけです。** 数値・規則・BOT のコードは変えないでください（不具合を見つけたら止めて報告）。

## 目的

⑬-5 では、読む腕（`S_Now`）と近視眼（`Gamma_Pure1T`）の大ダウンの差が **+0.059 回/戦** しかありませんでした。割った目盛りは 1 戦あたり約 1.6 個あるのに、大ダウンになったのは 0.41 個だけです。
差が小さい理由が次のどちらなのかを切り分けます。

- **BOT の欠陥**: 手加減すれば大技のターンまで目盛りを残せたのに、BOT がそれを選んでいない
- **ゲームの構造**: 残す手がそもそも無い、または残すと損が大きすぎる

## 入ったもの（2026-11-26・判断は変えない・乱数を引かない）

- BOT の診断 `NoteInstantDownDiag`（`AutoRunner.Terminals.cs`）。`downCancelRule = Instant` の時、大技の周期を持つボスで、ダウン中でない配線の判断ごとに数えます。
- ワーカーが `response.json` の隣に **`inst_down_diag.txt`** を書きます。
  - 1 行目: `inst_down_diag=a0,a1,…,a14`（生の数・ワーカーをまたいで足す）
  - 2 行目: 読める形の行（参考）
- 同じビルドに、前回の測定に入っていなかった BOT の変更（`downRerollPlan` = 振り直しを大事なターンに集める・Planned keep の修正）も入ります。今回の腕は既定のままで構いません。

## 数の意味（`a0`〜`a14`）

| 欄 | 中身 |
|---|---|
| a0 | 大技のターン（今割れば大ダウン）の判断の数 |
| a1 | そのうち、割る手があった |
| a2 | そのうち、割る手を選んだ |
| a3 | そのうち、撃破する手を選んだ |
| a4 | そのうち、目盛りがもう残っていなかった（前に割り切っていた） |
| a5 | 大技の 1〜2 ターン前の判断（目盛りあり） |
| a6 | そのうち、割る手を選んだ（チャージのターンなら無効・小技のターンならよろめき） |
| a7 | a6 のうち、割らない手もあった |
| a8 | a6 のうち、割らずに大技のターンまでに届く位置に残す手もあった（目盛りまで「大技までのターン数 × 1 ターンの与ダメの見込み」以内） |
| a9 | a6 の「抑える量」の合計（選んだ主攻撃 − 目盛りまでの残り + 1） |
| a10〜a13 | 抑える量の分布（≤5 / ≤15 / ≤30 / >30） |
| a14 | a7 について、割らない最良の手との効用の差の合計 ×100（HP 相当） |

「割れるか」は BOT の見積もりで判定しています（会心のぶれ・毒などで割れた分は入らない）。

## 出す物（⑭）

腕ごとに次の表を作ってください。

| 指標 | 式 |
|---|---|
| 大技のターンで割る手があった率 | a1 / a0 |
| 大技のターンで割った率 | a2 / a0 |
| 大技のターンに目盛りが残っていなかった率 | a4 / a0 |
| 大技の手前で割って捨てた率 | a6 / a5 |
| 捨てた時、割らない手があった率 | a7 / a6 |
| 捨てた時、届く位置に残せた率 | a8 / a6 |
| 抑える量の平均と分布 | a9 / a6、a10〜a13 |
| 我慢の損の平均（HP 相当） | a14 / 100 / a7 |

あわせて、生の 15 個の数（腕ごとの合計）と、⑬-5 と同じ形のダウンの計装（大ダウン・よろめき・溜めで無効・大技取消・被弾の 1 戦あたり）も載せてください。

## 判定の書き方（守ること）

- 数字が支える事と推測を分けて書く。原因を断定しない。
- 次の 2 つの見え方のうち、どちらに近いかを書く。
  - 「a8 / a6 が大きく、我慢の損が小さい」→ BOT が残せる目盛りを捨てている（BOT の欠陥）

- `S_Now` と `Gamma_Pure1T` の差も書く。
