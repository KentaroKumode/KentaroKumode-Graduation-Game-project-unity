## 目的

これから敵のパッシブを 1 ブロックずつ書き換えます（挙動は変えない書き換え）。各ブロックの後に、**ここで採る基準とランの結果が全件一致するか**を確かめます。その基準を採ってください。

## ビルド

- ブランチ **`perspective-swap-removal`** の、この依頼書と同じコミット（ブロック 0）。
- ブロック 0 で入れたのは計装だけです（挙動は変わらない）:
  - ワーカーが `response.json` の隣に **`enemy_skill_fires.txt`** を書く。中身は「敵のパッシブの id|トリガー<TAB>鳴った回数」。ワーカーをまたいで足してください。
- ヘッドレスのワーカーを、このコミットから作り直してください。

## 腕と条件

- 腕は **1 本だけ**: Super（今の既定の熟練者の腕・`S` と同じ設定）。
  - Naive・Optimal は要りません。書き換えるのは本体の敵のパッシブだけで、BOT は敵のパッシブを実行も模擬もしないため、腕の違いは「どの盤面に行き着くか」だけです（承認書の 4）。
- **`suppressLayer5HiddenBoss=False`**（シュヴァリエを出す）。シュヴァリエも書き換えの対象なので、検証の間はこの設定で固定します。
- そのほかの条件は ⑰ と同じ（難易度 0 / イベント ON / 嵐 ON＋T2 / 標準完成整備盤 9/9 / `measureNoExplore=True` / 200k `itt_clear.super.json`）。
- シード: `1,000,000 .. 1,009,999`（10,000 ラン）。**以後の全ブロックで同じシードを使う**ので、シードと実効状態の行をそのまま残してください。

## 出す物

1. **ランごとの結果の一覧**（基準ファイル）: 後のブロックと 1:1 で比べるための物。シードごとに、少なくとも次を残す。
   - 勝敗・到達した層・最後の HP・ゴールド・持ち物（id の並び）
   - 戦闘ごとの敵の id とターン数
   - 形式は、Neon がいつも「先頭 300 シードの一致率」に使っている物でよい。後のブロックで同じ道具で突き合わせられること。
2. **`enemy_skill_fires.txt` の合計**（敵のパッシブごと・トリガーごとの鳴った回数）。
   - 10,000 ランで **1 回も鳴らなかった敵のパッシブ**と、**100 回未満**のものを一覧にする（網羅の見張りの閾値を決める材料）。
3. 健全性: 例外 0・NotFound 0・Fallback 0・実効状態の行（`suppressLayer5HiddenBoss=False` が出ていること）。
4. 決定性の確認: 同じビルド・同じシードで **先頭 300 ランを 2 回**回し、2 回が全件一致すること（基準そのものがぶれないことの確認）。一致しなければ止めて報告。
