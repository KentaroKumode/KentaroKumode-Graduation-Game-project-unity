# ADR-0016 — 攻撃を端子ごとに当てる

## Status

**Proposed（2026-11-20）。** 作者が方針を確定した。2026-11-20 に Decision 1〜5 を実装（型チェックのみ・実機未確認）。数値の釣り合いは同じシードの対で測る（未測定）。
画面は合計を 1 回の攻撃として見せたまま（1 撃ずつの見せ方は残作業）。

## Context

- 攻撃の端子の出力は、合計して 1 回の攻撃にしていた（`CombatManager.Turn.cs` の `atkBase = 武器の攻撃力 + 攻撃の端子の合計 + 品の攻撃 +N + 消耗品 + 遺物`）。
  まとめる理由は GAME.md・ADR のどこにも書かれていなかった（作者「特に理由ないよね？攻撃 3 枚なら 3 回攻撃してもいい」）。
  敵の防御は割合で減らす式（ADR-0013 の逓減式）なので、分けても防御で不利にはならない。
- 2026-11-20 に説明に無い「1 ターン 1 回」の絞りを外したので、「攻撃が通るたび」の品は攻撃の回数だけ働く。
  攻撃を端子ごとに分けると、端子の組み方と秘宝の組み方がつながる（体験の大目標の「蹂躙に至るコンボが少ない」への答えの一つ）。
- 臨界の爆発は「閾値に届いた瞬間に決まり、ダメージは次の攻撃と一緒に固定ダメージで入る」の 2 段だった。
  2 段にしていたのは 2026-08-03 の修正（爆発を攻撃に足して倍率が丸ごと乗っていた不具合）の名残で、理由は残っていない。

## Decision

1. **攻撃は、攻撃の端子 1 枚につき 1 回当たる。** 1 回の量は、その端子の出力そのまま（作者 ①「そのまま」）。
2. **端子の外の攻撃（武器の攻撃力・品の攻撃 +N・消耗品・遺物）は、毎回に乗せる**（作者の決定）。攻撃の端子 3 枚なら武器の攻撃力も 3 回入る。
   大きな強化なので、数値は実装の後に測って詰める。
3. 会心の判定・与ダメ % の池・敵の軽減パッシブ・防御・「攻撃が通るたび」の品・ボスの目盛りを割る判定は、**1 回ごと**に起きる。
   与ダメ % の池などを ctx の上で足す処理は、2 回目以降に同じ % を足し直さない（〈分け身の賽〉で 2026-11-19 に直した漏れと同じ型）。
4. **臨界の爆発は、閾値に届いたその場でダメージを出す**（軽減無視・倍率は乗らない）。「次の攻撃に乗る」は廃止。
   これに合わせて 4 品を直す（作者 2026-11-20 承認）:
   - 〈火花読みの眼鏡〉: 爆発のたびに会心の判定をし、会心なら会心倍率の半分が乗る（代価はそのまま）
   - 〈荒砥〉: 「爆発した攻撃が通ると出血 +4」→「爆発のたび、敵に出血 +2」（後半はそのまま）
   - 〈爆破祭の小切手〉: 爆発のダメージそのもので敵が倒れたら +4G（文はそのまま）
   - 〈二度目の打金〉: 「爆発したターン」を読む（文はそのまま）
5. **〈分け身の賽〉（LEGENDARY）は廃止し、〈呪物の賽〉に置き換える**（攻撃を 2 回に分ける効果は、この ADR で意味が無くなる・作者 2026-11-20）。
   - 面 1〜6。店とイベントで秘宝を選ぶ時、LEGENDARY の重みが 1% → 3%（他のレア度の重みはそのまま・戦闘の報酬は含めない）。
   - 代わりに、秘宝を手に入れるたび（買う・報酬・イベント）最大 HP −3（ランの終わりまで・1 より下にはならない）。
   - 作者が 26 案から選んだ（目の値を動かす・振り直し・エスカレーション・役・分け身・占いの向きは不採用）。

## Consequences

- 触る所: 攻撃の処理（`CombatManager.Turn.cs` の主攻撃・分け身の 2 撃の処理を N 回に一般化）・臨界（`Keywords.AddHeatCore`・`Turn.cs` の爆発の予約消費）・
  画面（攻撃の見せ方）・BOT の見込み（`AutoRunner.Combat`）・DAMAGE_CALC_REFERENCE・GAME.md §6 / §7-4。
- 〈柱折りの発破筒〉の「爆発のダメージ」・超臨界爆発の ×1.5 は、その場の爆発の量で数える。
- 以前の測定値（クリア率・蹂躙率）とは直接比べない。
