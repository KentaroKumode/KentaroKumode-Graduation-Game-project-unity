# ADR-0014 — 端子の山札

## Status

設計はユーザーと確定 (2026-11-11)。実装はブランチ `terminal-deck`。**完成するまで main にマージしない。**

**実装済み (2026-11-11)**: 端子の定義と山札・戦闘への組み込み・BOT の挿し方と報酬の方策・戦闘画面と報酬の画面。
戦闘は常に山札で戦う ── 切り替え `TerminalCards.Enabled`、旧い配線の経路 (前ターンの配線の自動適用・`SanitizeWiring`)、
旧い特殊端子 (`SpecialTerminals.cs`・1 つ装着・層ボスの 2 択) は削除した (GAME.md §24)。
数値はすべて仮・未測定。この変更でこれまでのクリア率の測定値は全部比べられなくなる (基準値の測り直しは issue #102)。

## なぜ

- 端子は出目を足し込むだけの受け皿で、「6 は常に 3 より良い」= 配線が判断にならない (design-rejects の〈再演〉の節が書いている欠点)。
- 配線は前のターンのまま残り、介入は例外時だけ = 毎ターンの判断が無い。
- ビルドの中身は「持つだけで効くパッシブの束」で、このゲームでなくてはならない理由が薄い。
- 検討して落とした形: 敵が配線の形を問う規則 (ストレスが増えるだけ)・自動で早送り (時間短縮でしかない)・筐体の記録 (ゲーム性でない)・
  挿した出目を「式」にする (計算問題になる)・特殊端子を 1 つ装着して層ボスの 2 択で入れ替え (種類が効かない)。
- 残った形: **端子を山札にする**。種類を多く持ち、毎ターン違う手札に出目を合わせる。端子が「いつも同じ動き」でなくてよくなるので、
  使い捨て・常設・撃破で恒久のボーナスなどの幅が出る。

## 規則

1. **山札**: ランが端子の山札を持つ。開始は **攻撃 2・防御 2・充電 1** の 5 枚。攻撃・防御・充電も山札の 1 枚で、常設ではない。
2. **引く**: 戦闘の始めに山を切る。毎ターン 5 枚引く (2026-11-11 に 3 枚から。 出目は 3 個なので、 5 枚から 3 枚を選んで使う)。前のターンの手札は捨て札へ。山が尽きたら捨て札を切り直して続きを引く。
3. **挿す**: 出目は 1 枚に 1 個。端子に記載があればその数まで。**条件に合わない出目は挿せない** (不発)。行き先の無い出目は捨てる。
4. **種類**: 端子には種類がある (攻撃・防御・充電・補助)。「攻撃に挿した個数」などを読む既存の品・武器・敵の規則は、この種類で数える。
5. **攻撃の種類に 1 個も挿さないターンは攻撃しない** (ADR-0009 の規則のまま)。攻撃の種類を引けなかったターンは攻撃できない。
6. **振り直しは出目だけ。** 手札は変わらない。
7. **使い捨て**: 使うと、その戦闘中は山札に戻らない。次の戦闘ではまた入っている。永久に消える区分は作らない。
8. **常設**: 一度引くとその戦闘中ずっと場に残り、手札の枠を使わない。
9. **報酬**: 戦闘後は 2 択・エリートは 3 択・層ボスはレア 3 択。受け取らない選択あり。
10. **軸の端子**: 強さはその軸の偏重 (軸の品を持っている数) で決まる。報酬に出る確率を偏重で寄せる。誓約の封じは端子にも及ぶ。

## 端子 (基本 3 ＋ 57 種)

種類: 攻 = 攻撃 / 防 = 防御 / 充 = 充電 / 補 = 補助。数値は仮。正本は実コード `TerminalCards.cs`。

## 値付けの規則

1. 条件つきは、発動したら素の約 2 倍を返す。条件が厳しいほど上げる。
2. 準備役 (研磨盤・予熱器・計数器など) は、挿した出目を素の端子と同じに入れたうえで効果を足す。
3. % の効果のうち「別枠」と書いたものは、他の与ダメ% と足さずに掛ける (足すと終盤に薄まる)。
4. 別枠のダメージ (毒・出血・爆発) を作る端子は量を控えめに。軸の端子の主役は「溜まった資源を主攻撃に換える」側。

## 実装で決めたこと (ユーザーから「後で直せる範囲は任せる」と言われた分)

実装しながらここへ足す。大きい判断は末尾の「未決」へ。

- 端子の id = 表示名 (品と同じ規則)。
- 山札はラン単位 (`RunState.terminalDeck`)。山・捨て札・手札は戦闘単位。切る乱数は `GameRng` の専用キー。
- 既存の「配線」(ダイス → 攻撃/防御/充電) の値は、端子の種類から作る (補助は旧「特殊」、挿さない出目は「なし」)。
- 〈研ぎ澄まし〉の恒久の +1 は、同じ名前の端子で共有する (2 枚持っていれば 2 枚とも伸びる)。
- 旧い特殊端子 (11 種・1 つ装着・層ボスの 2 択) は、この形に置き換えて削除した (2026-11-11)。 切り替え `TerminalCards.Enabled` と
  旧い配線の経路も一緒に消し、 戦闘は常に山札で戦う。 `DiceTerminal.Special` (値 3) は「補助の種類に挿した出目」として残す。
- 〈返し鉤〉は〈返し針〉に改名 (ドット字に「鉤」が無い)。 〈絶縁体〉はシールド +出目 +3 (`TerminalCards.InsulatorBonus`)。
- ターンの頭は何も挿していない状態で始める (自動では挿さない)。 挿さない出目は捨てる (旧「未配置は攻撃へ自動合流」は無い)。
- 既存の消耗品 (回復・シールド・攻撃強化) は、 使い捨ての端子とは別に、 戦闘中も使える形で両方残す (#11)。
- 山札から端子を抜く・足す手段を店と休憩に置く (2026-11-11 実装・数値は仮):
  - 店: 端子の棚 3 枚 (`GameManager.TerminalShopSlots`・基本以外から重み付き・レアの重み 0.25・乱数キー "terminal.shop")。
    値段の素 コモン 16G / 使い捨て 12G / レア 36G に店の価格倍率 (進行・強盗の割増・商人の鈴) を掛ける。
    「山札から 1 枚抜く」= 15G + 10G × 店で抜いた回数 (`RunState.terminalShopRemovals`・上限なし・店の価格倍率は掛けない・休憩で抜いた分は数えない)。
  - 休憩: 回復の代わりに 1 枚抜く (無料・休憩の行動を使う)。
  - どちらも山札が手札の枚数 (3) を下回る抜き方はできない (開始の 5 枚も抜ける)。 人の画面も BOT も `ShopBuyTerminal` / `ShopRemoveTerminal` / `RestRemoveTerminal` を呼ぶ
    (BOT は自分の手番で本体の関数を呼ぶだけなので、 GameHooks の口は足していない)。
  - BOT: 棚は報酬と同じ点と足切りで選び、 払った後に 40G 残る時だけ買う。 抜くのは基本が 3 枚以上かつ基本以外が 2 枚以上の時に基本を 1 枚
    (防御・充電の多い方を先に・攻撃の基本は攻撃の種類が 3 枚より多い時だけ)。 店は 40G 残る時に 1 店 1 回・休憩は HP が 95% 以上の時だけ。
- 〈写し取り〉〈焼き切り〉〈保持器〉の対象は選べる (2026-11-11)。 候補 = 自分でない・常設でない・出目が 1 個も挿さっていない手札の端子
  (挿したが条件に合わず外れた端子も含む)。 画面: これらに出目を挿すと候補に「候補」、 決まった対象に「対象」の印。 候補の USB を、 その端子が挿さった口
  (か手札の抜け殻) へ落とすと決まる (その口への入れ替えより先に効く)。 選ばない・選んだ端子が候補でなくなった時は左端の候補。
  BOT: 写し取り = 素の点 (報酬の点・基本は 1) が最大 / 焼き切り = 最小 / 保持器 = 最大。 〈写し取り〉〈焼き切り〉の報酬の素の点の減点 (0.8) は外した。
  同じ種類の対象を取る端子を 2 枚同時に使っても、 対象は 1 つ (結果の欄が 1 つ・未対応)。
- 誓約の封じ: 封じた軸の端子は報酬と店の棚に出さない。 山札にある分は、 本体の封じの口 (AddStatus の毒・AddEnemyBleed・Kw.AddHeat・AddCharge・
  consShield・会心の判定) を通るのでそのまま止まる。 見込みを本体と揃えるため、 `TerminalCards.Resolve` も同じ資源を結果から落とす
  (`TerminalEnv.seal*`・攻撃とブロックへ入る出目は残す)。 軸の外の端子 (〈絶縁体〉〈蓄電池〉・基本の充電) も品と同じく口で止まる。 ホバーの説明に「誓約で封じられている」。
- ダイスの個数に上限は置かない: 画面は出目を 3 個ずつの列で並べ、 4 個目からは列を右へ足す。 本体と BOT は元から個数ぶん列挙する。
- 振り直しの判断の時も、 判断の写し (`TurnPause`) に場・盤面・状態を入れる (敵の攻撃は予告の近似)。
- 旧い配線の UI (`DeckMode` が false の時の左のパネル・`TermName` の「特殊」・`AnswerWiring(DiceTerminal[])`・`TurnPause.currentWiring`) を削除。
- ヴェスカ〈停滞する時間〉のリワークは issue #103、 基準値の測り直しは issue #102 (どちらもマージ後)。
- アイコンは 60 種とも確定 (`Game2DTerminalIcons.cs`)。
