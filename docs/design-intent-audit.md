# 設計意図の棚卸し（2026-10-17・作業用）

GAME.md のゲームの仕組みの章（§4〜§17）を読み、各要素を「意図をもって設計されたもの」と「なんとなく」に分けた。
**「なんとなく」は検討の対象にする。** 検討が済んだ項目は、結論を GAME.md の該当節へ書き戻し、この一覧から消す。

- 対象外: 文書の規約（§0〜§3）・世界観（§19）・ツールと BOT（§21）・未決（§23）・廃止の記録（§24）。
- 判定は **GAME.md の記述だけ**による。作者が理由を知っていても、文書に無ければ「なんとなく」側に入れている。
  理由があるなら、それを書き足せば A に移る。
- 何かを再提案する前に §24 と design-rejects.md を読む（CLAUDE.md）。

## 判定の基準

| 区分 | 条件 |
|---|---|
| **A 意図あり** | 何のための仕組みか（目的）と、なぜその形・その値か（理由）が書かれている。実測や導出で裏付けられているものを含む |
| **B 意図あり・値は仮** | 目的ははっきりしているが、数値が「仮」「暫定」「試作の値」のまま、または未測定 |
| **C なんとなく** | 目的も値の理由も書かれていない。旧システムからの持ち越し（×10 の換算など）で、今の仕組みに合わせて決め直されていないものを含む |

## 進め方

1. C の中から 1 つ選び、目的 →（必要なら）想定する遊び方 → 値、の順に決める。
2. 決めた結論を GAME.md の該当節へ書き戻し、この一覧から消す。
3. 値を変えるときは、変えたことをバランスの測定で確かめるか、測らずに出すかを、その都度決める（測るなら先に採否を取る）。
