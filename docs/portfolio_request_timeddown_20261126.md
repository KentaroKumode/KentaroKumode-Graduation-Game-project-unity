# 依頼: 「割る時を選ぶ」ダウンの規則の測定（2026-11-26）

`docs/portfolio_metrics_20261126.md` の続きです。結果は同じファイルに **「⑪」** として追記してください（①〜⑩ は書き換えない）。
**この依頼は測定だけです。** 規則と BOT の実装はこちらで済ませてあります（下の「入ったもの」）。数値・規則は一切変えないでください。

## 目的

作者の方針: **ボスのダウン（目盛り）を、先を読む人が確実に得をする強力なアドバンテージにする。**
⑩-2 の案を作者が決めた形で実装しました。これで「割る時を読む力」が勝敗に効くようになったかを測ります。

## 入ったもの（既定で有効・2026-11-26）

規則の正本は `Assets/Scripts/CombatSystem/BossDown.cs` の `Classify`、説明は GAME.md §6-15 の冒頭の引用と DAMAGE_CALC_REFERENCE の「ボスのダウン」。

- **ダウンの種類は、ダウンが来たターンで決まる**（既定 `downCancelRule = Timed`）
  - 山場（大技・構え・〈業火の予兆〉）のターン → **大ダウン**（攻撃しない・山場を取り消して周期を頭へ・受けるダメージ ×倍率）
  - チャージのターン（山場の 1 ターン前）→ **無効**（溜め中は怯まない・敵は普段どおり溜める・目盛りは消える）
  - それ以外 → **よろめき**（攻撃しない・倍率なし・周期はそのまま）
  - 大ダウンを取るには、チャージのターンに通常攻撃で割る。周期を持たない敵は今までどおり
- ひびで割れた分は常によろめき（山場に来たら無効）。〈柱折りの発破筒〉の延長は大ダウンのまま
- まとめて割っても 1 ターン。大ダウンの倍率は 2 つ目から 1 つにつき +0.5（2 つで ×2.0）
- **BOT**: 目盛りを割る価値に、次のターンの種類を入れた（チャージの前に割ると負＝山場を止める機会を捨てる損・チャージで割ると山場を消す得）。2 ターン先読み（`deckLookahead`）もこの見込みを使う。`downAimPolicy=Aim` は `Timed` では何もしない
- **新しい測定の口** `downTimingAware`（既定 True）: False にすると、BOT は旧い規則のつもりで目盛りの価値を見積もる（本体の規則は変わらない）。**知る腕と知らない腕の差が「割る時を読む価値」**
- **新しい計装**: サマリーのダウンの行に「溜めで無効 N (1 戦 x)」。実効状態の行に「ダウンの規則を BOT が知る … (downTimingAware=…)」と「ダウンの大技の取り消し … (downCancelRule=Timed)」

## 準備（必須）

1. **ヘッドレスのワーカーを今のソースから作り直す**（`HeadlessWorkerBuild/DiceBoundHeadless.exe`）。古いビルドには新しい規則が入っていない。
2. 各腕 300 ランの事前確認: 例外 0・NotFound 0・Fallback 0。実効状態の行で `downCancelRule=Timed`（旧い規則の腕だけ `ChargeOrHeavy`）と `downTimingAware` の値が腕の定義どおりか。
3. ボス戦のダウンの行に「溜めで無効」が出ていること（`S_T` で 0 なら、規則が効いていない。止めて報告）。

## 判定の書き方（守ること）

- `S_T` が `S_Tu` に有意に勝つ → 「割る時を読む力が勝敗に効く（戦闘に読みの深さが生まれた）」。差の大きさを pp で、大技の取り消しの差を回数で添える
- 差が出ない → **「深さが無い」と断定しない**。「この BOT の見積もり（1 手の価値＋2 ターン先読み）の上では差が出なかった」と条件付きで書き、知る腕と知らない腕で**溜めで無効の数**と**大技の取り消しの数**が変わったかを必ず添える（変わっていなければ BOT が規則を使えていない可能性が高い）
- `S_T` − `S_old` は難易度の報告だけ。数値の調整案は書かない（凍結の段取りは作者が決める）
- 推測で原因を断定しない。数字が支える事と推測を分けて書く
