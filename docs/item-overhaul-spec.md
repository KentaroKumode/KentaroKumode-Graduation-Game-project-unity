# アイテム体系オーバーホール設計書（Claude 実装引き継ぎ用）

## 0. 目的と合意事項サマリー

本設計書は [experience-goal.md](experience-goal.md) の二大体験を同時に成立させるための、アイテム・ショップ・端子の包括的改修案である。

1. **(1) 俺ツエーの回（掛け算・規則破壊）** — 軸の特化や「資源軸 × 戦い方（山札・役・配線）」の噛み合いで力が乗算的に伸び、ボスを溶かせる。
2. **(2) 引きの悪さを知識で乗り切る回** — 引きが弱くても、ショップ（軸指定リロール・戦術消耗品）、端子のピックと削除、ボスのダウン・大技周期、嵐の踏み方といった知識と判断で勝ち筋を作れる。

### インタビューで確定した設計方針（2026-11-20）

| 項目 | 決定事項 |
|---|---|
| **総品数とリワーク** | **大幅なアイテム増加を許可する**。同時に、既存の重複・下位互換・純足し算・旧仕様残骸の秘宝は必ずリワークする。 |
| **誓約（Oaths）** | **既に削除予定**。新設軸にも誓約は置かない。特化インセンティブは「偏重参照・入り口条件・規則破壊・締め LEGENDARY・ショップ軸指定リロール」で担保する。 |
| **軸体制** | 既存 6 軸（会心・出血・毒・臨界・充電・シールド）＋ 金 に加え、**「山札軸（仮称：機巧）」** と **「役軸（仮称：賽目）」** の **2 偏重軸を新設（計 8 軸体制）**。 |
| **ショップの特化保証** | **追加コストを払うことで、指定した 1 軸の秘宝が強い重みで出現する「軸指定リロール」** をショップに導入する（プール膨張対策＋終盤の金余り解消＋能動的なビルド構築）。 |
| **クロス軸シナジー** | 軸内の「資源 × 山札/配線/役」を主軸とし、クロス軸変換は **「偏重条件つき・高レア（GOLD / LEGENDARY）限定」** で追加する（10/31 時代の「安い変換器の何でも買い」再発を防止）。 |
| **戦術消耗品** | ショップの消費 3 枠を **「1 枠目＝回復固定 / 2 枠目＝防御・火力から 1 種 / 3 枠目＝戦術消耗品固定」** に再編（UI 枠数不変・回復供給を維持）。消耗品連動秘宝も追加する。 |
| **スコープ** | 秘宝（新規＋リワーク）／戦術消耗品＋連動秘宝／端子の山札（新端子＋調整）／嵐・ショップ・金経済マクロ秘宝。 |

> **数値の扱い**: 本文中の具体的な数値・品名（仮称）はすべて叩き台である。実装時は [experience-goal.md](experience-goal.md) の作法に従い、**フェーズごとに同一シードの対比較（`paircmp.py` / Super・嵐あり + T2）** で較正すること。

## 1. 絶対制約・再提案禁止事項（実装前チェックリスト）

実装時に以下を破らないこと（出典: [GAME.md](GAME.md) / [design-rejects.md](design-rejects.md) / [experience-goal.md](experience-goal.md)）。

1. **単一品で蹂躙を成立させない**（例外は `[剣の舞]` 4 枚集約の〈無銘の剣舞譜〉のみ）。締め LEGENDARY は「その軸を深く組んだときだけ壊れる」設計にする。
2. **説明文に書いていない裏制限（隠し上限・1 連鎖 1 度など）を入れない**（2026-11-19 作者決定）。無限ループ防止は**品のテキスト上の自然な制限**で止め、`ChainGuardDepth = 200` は不具合検出網のまま残す。
3. **「X が X を生む（割合還元）」の自己循環ループを量産しない**（[design-rejects.md](design-rejects.md) 2026-11-19）。軸ごとに異なるベクトルの規則破壊を割り当てる。
4. **「すべての〜に効く」純足し算の秘宝を作らない**（何を持っても働く品は掛け算にならない）。
5. **見えない出目の書き換え禁止**（LED の表示値＝配線に使える値を厳守・[GAME.md §8-1](GAME.md)）。
6. **「全ダイス最大」や低確率ゾロ目専用を前提とした死に条件を作らない**（3 ダイスの 2 個そろい・役全般・リロールで狙える条件にする）。
7. **既存システムが強く罰している状態（低物資など）を報酬にする軸を作らない**（〈渇き〉の教訓）。嵐連動は「嵐の段階を能動的に踏む/戦う選択」に紐づける。
8. **決定性の厳守**: 新規のランダム抽選は必ず `GameRng` の専用キーを使う。`CombatContext` への新フィールド追加時は `perTurn` / `decay` / `persistent` の 3 区分を XML コメントに明記し、`BeginNewTurn` にリセットを書く（少数箇所なら `accumulatedValues` / `nextTurnBuffs` を使う）。
9. **ID 直書き禁止**: 跨ファイル参照する品名・端子名・消耗品名は `Ids.cs`（`ItemIds`）または `TerminalIds` に定数を追加する。

### 2-3. ショップ「軸指定リロール（Axis-Focused Reroll）」

対象: `Assets/Scripts/ItemSystem/Shop/ShopManager.cs`、`ShopInventory.cs`、`GameManager.Shop.cs`、ショップ UI、BOT (`AutoRunner.Shop.cs`)

**狙い**: 8 軸（230〜250 品規模）でのプール希釈を防ぎつつ、終盤に余るゴールドを「狙った軸・締め LEGENDARY を掘りに行く投資」へ変換する。

- **API**: `ShopManager.TryReroll(RunState run, string focusAxis = null)`（既存の `TryReroll(run)` は `focusAxis = null` のラッパーで後方互換維持）。
- **コスト式（仮置き）**:
  - 通常リロール: 既存の `Current.CurrentRerollPrice` のまま。
  - 軸指定リロール: **`Current.CurrentRerollPrice + AxisRerollSurcharge`**（仮値 `AxisRerollSurcharge = 15G`、または `max(12, ceil(CurrentRerollPrice × 1.5))`）。層進行による価格倍率（`ProgressPriceMultiplier`）は掛けないか緩やかに掛ける（通常リロールと揃え、A/B で較正）。
  - リロール回数 `Current.rerollCount` は通常リロールと共有し、連続で回すほど高騰する（無限掘り防止）。
- **抽選ルール（`PickItemByKind`）**:
  - `focusAxis != null` のとき、パッシブ枠（5 枠）の抽選で `item.axis == focusAxis` の候補の出現重みを **×6.0（仮置き）** にする（確定 5 枠全部同軸にはせず、期待 2.5〜3.5 枠が指定軸になるバランス。指定軸の未取得品が尽きたら残りは通常プールから引く）。
  - 併せて、店の端子の棚（3 枠）のうち未売却枠も `def.axis == focusAxis` の重みを上げる（山札と秘宝を同時に狙える）。
  - レア度抽選（`tierWeights`）と `呪物の賽`（LEGENDARY ×3）は通常通り独立して適用する。
  - 乱数キーは通常リロールと同じ系統を使いつつ決定性を維持。
- **UI**: ショップのリロールボタン横に「軸指定」プルダウン／タブ（なし・8 軸から選択・現在の自分の偏重数を横に表示）を置き、選択時はボタンの金額表示が追加コスト込みに変わる。
- **BOT 方針**: `AutoRunner.Shop.cs` に「現在最も深い偏重が 3 以上かつ残金が閾値以上なら、その軸を指定してリロールする」方策を追加し、A/B で通常リロールと比較検証する。

### 2-4. ショップ消費 3 枠の再編（戦術消耗品の常設流通）

対象: `Assets/Scripts/ItemSystem/Shop/ShopManager.cs`（`Generate` / `TryReroll`）、`Assets/Scripts/GameLoop/Ids.cs`

現在のショップ消費 3 枠は「枠 0: 回復固定 / 枠 1〜2: シールド・攻撃強化（2 系統を両方並べる）」になっている。これを以下へ変更する（**棚の総枠数 12・消費 3 枠は不変**）。

| 枠 | 現行 | 変更後 |
|---|---|---|
| 消費枠 0 | 回復（`cons_heal`・T1〜T4）固定 | **変更なし（回復固定）** |
| 消費枠 1 | シールド or 攻撃強化 | **シールド（`cons_def`）または攻撃強化（`cons_dmg`）から 1 系統を抽選**（T1〜T4・`古い手紙` 差し替えもここで維持） |

- 戦術消耗品は Tier 1〜4 の単純数値階段にせず、**1 種 1 機能の固有アイテム**（レア度 BRONZE〜LEGENDARY、価格 5〜10G 帯）として設計する。

### 3-3. ADR-0016（端子ごとの多段攻撃）に伴う既存品の挙動監査

[0016-per-terminal-hits.md](adr/0016-per-terminal-hits.md) で攻撃端子 1 枚につき 1 撃になったため、以下の既存品は実装・測定時に挙動を確認し、意図的な線引きを行う。

- **`毒針の指輪` (BRONZE / 毒)**: 現行は「攻撃が通るたび、攻撃端子を挿したダイス個数ぶん毒」→ 3 枚挿しで 3 撃 × 3 = 1 ターンに毒 +9 は BRONZE 1 品として破格すぎる。**「攻撃が通るたび毒 +1（3 枚挿しで計 +3）」** または **「1 ターン 1 回、攻撃端子を挿したダイス 1 個につき毒 +2」** へ整理を推奨。
- **`抜き打ちの作法` (GOLD / 会心)**: 「戦闘の最初の 2 回の攻撃は必ず会心」は攻撃端子 2 枚挿しで 1 ターン目に尽きる。**「戦闘の最初の 3 回の攻撃」** または **「戦闘の最初の 2 ターン、最初の 1 撃は必ず会心」** に見直し候補。
- **`血桜` (LEGENDARY / 出血)**: `OnPreDealDamage` が毎撃発火するため、多段攻撃 × `戻り血の頭骨` で極端な出力になる。出血軸の象徴として許容するか、他 7 軸の締め LEGENDARY の出力と並べて測定し、`+スタック×3` の係数で調整する。
- **一撃重撃型（攻撃端子 1 枚のみ）の支援**: 現行の `一の矢`（BRONZE・攻撃 1 個のみ会心 +30%）だけではアーキタイプにならない。第 7 軸・第 8 軸および §6 の追加品で一撃重撃ビルドの相方を用意する。
