# 依頼: 混乱ゲージの検証（2026-11-26）

`docs/portfolio_metrics_20261126.md` の続きです。結果は同じファイルに **「⑮」** として追記してください（①〜⑭ は書き換えない）。
**この依頼は測定だけです。** 数値・規則・BOT のコードは変えないでください（不具合を見つけたら止めて報告）。

## 目的

⑭ で、HP の目盛りではダウンを大技に合わせられないことが分かりました。1 回の攻撃が目盛りを平均 241 越え、割らない手は攻撃を丸ごと止めるしかありませんでした。
そこで、目盛りを **混乱ゲージ** に置き換えました（作者の決定・GAME.md §6-15）。次の 3 つを測ります。

1. **読む腕は、近視眼より報われるか**（作者の目標: 近視眼の戦闘より 3 層クリア率で 5 pp 前後）
2. ダウンが大技のターンに重なる割合は増えたか（⑬-5・⑭ との比較）
3. 難易度はどう動いたか（経験者の目標は 40% 前後・報告だけ）

## 入ったもの（2026-11-26）

- **混乱ゲージ**（`BossDownState.AddGauge`・値は `BossParams.DownGauge`）
  - 溜まる量: 攻撃のカードに挿して発動したダイスの「止まった面の数字」の和。出目 +N などの補正は入らない。配線の時点で溜まる。
  - 満ちた瞬間: `Instant` と同じ効き方（大技のターン = その場で止まり、次のターンは大ダウン ×2.0 / チャージ = 無効 / 小技 = よろめき）。
  - 満ちたら 0 に戻り、満タンが ×(1 + 増え方) で増える。大ダウンのターンは溜まらない。
  - 敵が行動した後に足された混乱（〈黎明〉〈落城の礎石〉ほか）は預かり、次のターンの頭で最初に入れる。
  - 満タン（基本・増え方）:

    | ボス | 基本 | 増え方 |
    |---|---:|---:|
    | 深さ 3 の 3 体（`boss_layer2/3/4`） | 27 | +30%（沼の主 `boss_layer3` だけ +60%） |
    | 審判官 `boss_layer5` | 45 | +25% |
    | シュヴァリエ `boss_layer5_hidden` | 45 | +35% |
    | 灰燼の王 `boss_layer6` | 36 | +25% |
    | ヴェスカ p1・p2 | 30 | +40% |
    | ヴェスカ p3・p4 | 45 | +40% |

- 目盛りを動かしていた品は「混乱 +N」の固定値（一覧は `DAMAGE_CALC_REFERENCE.md` の「ボスの混乱ゲージ」）。
- 液晶に「混乱 N/M」と「大技まで N」を表示。
- BOT:
  - 候補の手ごとに溜まる量を、本体と同じ関数（`CombatManager.GaugePips`）で数える。品の「混乱 +N」も、配線の時点で条件が分かる分は足す（`ItemGaugeEstimate`・撃ごとの品 × 撃の数・1 ターン 1 回の品）。【起爆】と臨界の爆発は数えない（撃の中で起きるかが決まるため）。
  - 満たさずに「大技のターンに満たせる位置」に残す手に、大技を止める得の一部を足す（`downGaugeReadyShare`・既定 0.5）。
  - 規則を知らない腕（`downTimingAware=False`）と近視眼の腕は、この価値を見ない。
- 前回の測定に入っていなかった BOT の変更（`downRerollPlan`・Planned keep の修正）も、このビルドに入る。
- 診断 `inst_down_diag.txt`（⑭ と同じ 15 個の数）は、ゲージで数える。「割る」は「満たす」、「抑える量」は「溢れた量」と読み替える。

## 準備（必須）

1. ヘッドレスのワーカーを今のソースから作り直す。
2. **事前確認（各腕 300 ラン）**:
   - 全腕で 例外 0・NotFound 0・Fallback 0。
   - 実効状態の行が腕の定義どおりか。
   - **ゲージが実際に満ちているか**: ボス戦のダウンの計装（大ダウン・よろめき・溜めで無効）が 0 でないこと。0 なら止めて報告。
   - 1 戦あたりのダウンの数（大ダウン＋よろめき＋溜めで無効）を、ボスごとに出す。参考までに、目盛りの時（⑬-5）は 1 戦あたり約 1.6 回。**1 戦 4 回を超えるボスがあれば止めて報告**（満タンの値が小さすぎる）。
   - 1 ターンに溜まる量の平均（BOT のログ `[配線] 混乱 N +M` の M、または診断の数から出せる範囲で）。

## 共通の条件（⑬-5 と同じ）

- 難易度 0 / イベント ON / 嵐 ON＋T2 / 標準完成整備盤（9/9）/ `measureNoExplore=True` / `downCancelRule=Instant`（既定）/ `v3.ledgerContinuous=True`（既定）

- シード: `1,000,000 .. 1,009,999`（各腕 10,000 ラン・全腕で同一）

## 判定の書き方（守ること）

- **`S_Now − Gamma_Pure1T` について**: 差と信頼区間をそのまま書く。目標の 5 pp 前後に届いたかを書く。
- 届かなかった時は「読む価値が無い」と断定しない。「この BOT の見積もりの上では」と条件付きで書き、大技取消の差と、⑮-4 の「届く位置に残せた率」「溢れた量」を必ず添える。

- 推測で原因を断定しない。数字が支える事と推測を分けて書く。
