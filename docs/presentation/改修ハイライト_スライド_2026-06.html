Phase 1 ─ 旅団契約システム

仕組み

  • 12 旅団と前哨基地で契約
  • 各旅団 30% 独立抽選で提示
  • 維持費: L1=3G / L2=6G / L3=9G/層
  • 3 層必須で L3 (一足飛び不可)
  • 解除: HP≤20% / G不足 / 敵対契約取得
  • L3 没収時は維持費9G失う

主要効果軸

  • 戦闘系: 傭兵団 / 暗殺教団 / 狩猟旅団
  • 守備系: 騎士 / 影武者一座
  • 経済系: 商業連合隊 / 補給キャラバン
  • 支援系: 医術官 / 戦術家 / 錬金術師
  • 特殊: 宣教師 (希望保護) / サーカス (windfall)

Phase 6 ─ upgrade 割引 + 連続値 LiftScore

問題: 5 段 Tier の粒度不足

  • 同家系 LV3 / LV4 が同 Tier に丸まり区別不能
  • RawScore (S=4...D=0) では 4-fold 幅、 武器 WeaponTierBonus (1-10) と不整合
  • BOT が「LEGENDARY 無視、 GOLD 保持」 を最適解と判断 → 設計上の罠

解 1: upgrade 割引 (1G/Tier段)

  • 同家系下位 Lv 所持時、 上位提示が Tier 1 段差 = 1G の超格安に
  • LV2 所持 + LV4 提示 → 2 段差 → 2G
  • 「希少品を見たら取る」 体験を取り戻す

解 2: 連続値 LiftScore (案 A)

  • Tier バケットではなく z-score 加重和を直接スコアに
  • 同 Tier 内序列が自動序列化
  • 家系 Lv 補正: I=0 / II=0.5 / III=1.0 / IV=1.5

BuyPriorityPass 三段 tiebreak

  1. Score (Tier バケット + 特売補正)
  2. LiftScore (連続値、 案 A) ← 新
  3. ΔPower / G (コスパ)
Tier 表は人間用 snapshot、 BOT 判定は連続値 LiftScore の二系統運用。

Phase 7 ─ ΔPower 提示時 + pick/retention 分析

問題: ΔPower の selection bias

  • dice_bone が +18.5 ΔPower (実態は BRONZE で並)
  • 非取得側 = 早期死亡群 で歪み
  • 真理 / 剣の舞集約 も同じ bias

解: ΔPower 提示時 (offered cohort)

ΔPower提示 = avg(取得∧提示)
            − avg(非取得∧提示)

同じ「提示された」 母集団で比較 → 早期死亡群を除外 → 真の貢献

  • dice_bone: +18.5 → 推定 +1〜+3
  • BD バイアス: +68 → +30 程度に半減

pick率 / 保持率 分析 (新規)

ラベル条件意味
★定番pick≥70% & 保持≥70%取って残す本命
⚠序盤要員pick≥70% & 保持<40%序盤強・後半捨
○常用品pick≥70%標準的活用
◇隠れ強pick<20% & 保持≥70%取れば離さない
△マイナーpick<20%あまり使われない
⚠は「終盤に置換される設計」 が機能している証拠。 ◇は「BOT 評価不足」 で Tier 上げ候補。
