# pixelfx の分解ライブラリ

pixelfx の効果を**部品 (札)** に分けて、 部品ごとに「どのコードが何を再現しているか・単独だとどう見えるか・
いつ出るか・ほかの部品とどう重なるか」をまとめた資料。 新しい効果を自前で書く時に、 ここから部品を選んで組む。

## 置き場所と形

| 場所 | 中身 |
|---|---|
| `library/<分類>/_components.md` | その分類の**部品の語彙**。 部品の種類ごとに、 描く関数・式・パラメータ・使いどころ・作り分け |
| `library/<分類>/<効果>.md` | 効果 1 つの分解。 冒頭に全体の組み立て、 `### \`札\`` の節が部品 1 つ |
| `lab/annotated/<分類>/<効果>.js` | 元の効果に札を足した写し (`p.tag = "…"` と `ps.src = "…"` を入れただけ。 動きは同じ) |
| `lab/annotate_*.py` | 上の写しを作る置き換えの一覧 (元の行 → 札を足した行) |
| `lab/setup.mjs`・`lab/layers.mjs`・`lab/page.py` | 分解の道具 |

絵は git に入れない (`*.png` は管理外)。 次の手順で、 いつでも作り直せる。

```sh
python Tools/pixelfx/lab/annotate_fire_1.py && python Tools/pixelfx/lab/annotate_fire_2.py   # 札を付けた写しを作る
node Tools/pixelfx/lab/layers.mjs fire --out <出力先>      # 部品ごとの絵・年表・重ね直しの検査
python Tools/pixelfx/lab/page.py <出力先>                  # 見る頁 (<出力先>/index.html)
```

出力先の `<分類>/<効果>/`:
- `full.png` … 元のまま
- `layer_<札>.png` … その札だけを描いた物
- `stack_<n>_<札>.png` … 札を出てきた順に足していった物
- `recomposed.png`・`diff.png` … 札ごとに別々に描いて後から重ねた物と、 元との違い
- `manifest.json` … 札の表 (種類・出ている時間・山場・画素の数・コマごとの量)・重ね直した時の違い

## 札の仕組み (分解が正しい理由)

- 画素を書く口は 3 つしかない: `put` (不透明・ディザで薄くする)・`add` (光・足し算)・`blendPx` (半透明・下の色へ混ぜる)。
  実験室はこの 3 つで札を見て、 選んだ札だけを書く。 `painter.js` のほかの描画は全部この 3 つを通る。
- シミュレーション (粒の動き) と乱数は変えない。 だから、 描く札を絞っても、 残した部品の形と動きは元と 1 画素も違わない。
- 粒は「出どころ / 種類」で札が付く (`burst/SPARK`・`cap/FIRE`)。 炎が消えて煙になった物は出どころを引き継ぐ
  (`cap/SMOKE`)。 燃える塊の尾は `<出どころ>>trail/FIRE`。
- **別々に描いて重ねても同じになるか**は `manifest.json` の `recompose.differingPct` で分かる。 炎の効果は 0〜2%。
  違いが出るのは、 (1) 半透明の煙が下の色に混ざる所、 (2) 部品どうしが交互に描かれて上下が入れ替わる所だけ。
  つまり、 この道具の効果は「独立した部品の重ね合わせ」として設計してよい。

## 読み方 (AI 向け)

1. 作りたい物に近い分類の `_components.md` を読む。 部品の種類と、 どの効果で一番うまく使われているかが分かる。
2. その効果の `<効果>.md` を読む。 部品の出る順 (年表) と、 部品ごとのパラメータが分かる。
3. `lab/annotated/` の写しで、 札の付いた実際のコードを読む。 札の名前で検索すると、 その部品のコードに直接行ける。
4. 新しい効果は `src/fx/dicebound/` に書く。 既存の部品の関数 (`flameTongue`・`firePuff`・`band` …) を呼び、
   パラメータを変えて組む。 形を自分で描き起こすのは、 部品に無い物だけ。
5. 書いたら `layers.mjs` で分解して、 手本にした効果と部品の量・時間を見比べる。
